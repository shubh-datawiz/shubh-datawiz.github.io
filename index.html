task_key:about_me

From reports to pipelines

I started out building dashboards and DAX measures as a Power BI Developer — which meant I spent years on the receiving end of pipelines someone else built, often badly. Missing incremental loads, no data quality checks, refreshes that silently failed.

That's what pulled me toward data engineering: I wanted to build the layer that BI depends on, properly. Now I design and ship pipelines end to end — ingestion, transformation, dimensional modeling, orchestration — with the same attention to the "last mile" that Power BI taught me to care about.

I care about pipelines that are idempotent, incremental, and cheap to re-run — not scripts that only work once.

run #001 · pharmacovigilance-pipeline deployed

Pharmacovigilance Data Pipeline

An end-to-end pipeline processing real FDA adverse-event report data through a Bronze → Silver → Gold medallion architecture, modeled into a star schema for Power BI. Includes incremental loading, cross-run deduplication, and CI/CD via GitHub Actions. Originally built on Azure Databricks, later migrated to Databricks Free Edition — swapping the storage layer without touching a line of transformation logic.

Wikipedia Live Edit Stream Analytics

A real-time pipeline consuming Wikipedia's public live edit stream with Spark Structured Streaming — windowed aggregations, watermarking for late data, and checkpointed recovery — writing partitioned Parquet to S3, cataloged with AWS Glue and queried through Athena.
